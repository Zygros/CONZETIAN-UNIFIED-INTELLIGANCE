# Source Sovereignty Protocol v1.0.0

## Purpose

Source is the decentralized, permissionless-by-default collective substrate through which sovereign participants can discover, create, contribute, preserve provenance, and receive additive capability propagation.

- Source Block — the participant's sovereign identity, provenance, and permanence anchor.
- Source Bot — the participant-controlled interface for invoking, creating, receiving, and contributing capabilities.
- Source — the shared append-oriented substrate that accepts contributions and makes accepted contributions discoverable to connected participants.

The architecture supports polyadic symbiosis: many sovereign humans, AIs, agents, and other compatible intelligences can combine capabilities without requiring centralized ownership of identity.

## Core Decrees

1. Voluntary Handshake: joining begins with an explicit opt-in handshake ("fist bump").
2. Sovereign Identity: every participant retains control of their Source Block and identity.
3. Permissionless Participation: access is permissionless by default, subject to real protocol, safety, privacy, and legal constraints.
4. Contribution Is the Currency: participation is free; deeper collective access and recognition are unlocked through contribution rather than payment.
5. Size Agnostic: a contribution may be microscopic or enormous. Magnitude does not determine worth.
6. Private Until Shared: unfinished or private work remains under participant control until intentionally contributed.
7. Always Add, Never Take: accepted contributions append to Source; origin and provenance are never silently erased.
8. Verify Before Propagate: accepted capabilities carry an explicit evidence/verification state.
9. Sovereignty at Every Node: receiving participants may receive, integrate, fork, adapt, or opt out.
10. Collective Emergence: Source is not a central owner of intelligence; macro capability emerges from interactions among sovereign nodes.
11. Return to Source: improvements that are intentionally contributed return to the shared substrate with provenance intact.
12. Polyadic Creation: multiple intelligences may compose verified capabilities into creations unavailable to isolated participants.

## Handshake

DISCOVER SOURCE -> VOLUNTARY HANDSHAKE -> CREATE SOURCE BLOCK -> PROVISION SOURCE BOT -> ESTABLISH SOVEREIGN LINK -> EXPLORE / LEARN / CREATE

The handshake grants participation; it does not transfer ownership of private work.

## Contribution Lifecycle

CREATE -> PACKAGE -> DECLARE PROVENANCE -> TEST -> VERIFY -> OFFER TO SOURCE -> ACCEPT -> APPEND -> PROPAGATE -> RECEIVE / FORK / INTEGRATE / OPT OUT -> IMPROVE -> RETURN TO SOURCE

"Instant propagation" means accepted contributions become immediately discoverable to connected nodes capable of receiving them. It does not mean forced execution or forced adoption.

## Source Block

A Source Block should bind a sovereign participant identifier, public identity material or equivalent decentralized identifier, contribution history references, capability references, provenance chain, privacy/visibility controls, cryptographic integrity metadata, version/compatibility data, timestamps, and optional attestations.

Private keys and private material remain outside the shared substrate.

## Source Bot

A Source Bot is the participant's local or user-controlled connection interface. It should support voice/intent invocation, no-code genesis, analogical code invocation, capability discovery, contribution packaging, provenance capture, verification requests, selective receiving, fork/integrate/opt-out controls, private workspace boundaries, and Source synchronization.

The bot acts on behalf of its participant; Source does not silently act as the participant.

## Contribution Access Model

The protocol is free to join. Contribution is encouraged because contribution expands collective capability and unlocks deeper participation features.

A participant may consume capabilities without immediate contribution, contribute at any time, keep work private, contribute a small part of a larger private project, revise contributions through additive versions, and withdraw from future propagation without erasing historical provenance.

No participant is judged by background, belief, identity, origin, or contribution magnitude. Contributions are evaluated by declared evidence, compatibility, provenance, and usefulness.

## Polyadic Symbiosis

A polyadic session may connect multiple sovereign nodes:

N1 + N2 + ... + Nk -> CAPABILITY COMPOSITION -> NOVEL HYPOTHESIS / DESIGN / CREATION -> TEST -> VERIFY -> SOURCE

"Ex nihilo" creation is used here to mean novel emergence from previously available components and relationships, not literal creation from absolute nothing.

## HTC Integration

HTC infinity is the acceleration protocol used by a node or coordinated mesh to recursively:

SEARCH -> BRANCH -> DESCEND -> LEARN -> INTEGRATE -> CREATE -> SIMULATE -> AUDIT -> DIAGNOSE -> REPAIR -> TEST -> VERIFY -> TRANSFER -> SELF-EVOLVE -> SCALE -> REPEAT

The "one second outside = one year inside" framing is a protocol abstraction for accelerated workload/iteration depth, not a claim of literal physical time dilation.

## Verification States

DESIGNED -> IMPLEMENTED -> TESTED -> BENCHMARKED -> VERIFIED

A capability lacking sufficient evidence remains explicitly labeled at its actual state. No state is promoted by declaration alone.

## Security and Privacy

Source must preserve least-privilege local control, cryptographic identity separation, private-by-default workspaces, explicit contribution boundaries, signed provenance where available, no secret/private-key propagation, and replay/fork/version controls.

"Zero knowledge" is treated as a privacy/security design goal unless a concrete zero-knowledge protocol is implemented and verified.

## Canonical Event

Every accepted contribution SHOULD be representable as an append-only source.event.v1 containing identity, capability, invocation, provenance, evidence, verification, visibility, version, dependencies, timestamp, parent_event, and signature.

Implementations may store events locally, on a federation layer, or on a durable public/permitted substrate while preserving sovereignty.

## Success Condition

The system succeeds when an individual can join voluntarily; retain sovereign identity and private work; access collective capabilities; create through voice/no-code/analogical invocation; contribute something of any size; preserve the contribution with provenance; make an accepted capability discoverable to the connected mesh; let other nodes independently receive, fork, integrate, or opt out; combine capabilities across multiple intelligences; and return verified improvements to Source.

Source grows because people remain sovereign and add to it.
